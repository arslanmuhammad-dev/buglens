# Regression round — 22 October 2026

Plan: run the existing local suite on an isolated database, reproduce dashboard response-order/navigation races and screenshot-removal validation problems, add focused regression coverage, fix confirmed failures, then repeat the relevant local and hosted flows. Release verified fixes through a feature PR and the existing Vercel project.

Baseline: lint/typecheck, 27 unit/integration tests and all 16 existing Chromium/mobile scenarios passed.

## Confirmed failures and fixes

- A delayed report GET could replace a newer selection or reopen a report after navigating away. Selection versions now discard stale successes/errors and leaving a report invalidates pending reads.
- Completion of a status/note change could reopen a report the user had left. Mutation refreshes now apply only to the still-selected report; list refreshes read the current filters rather than a stale callback's filters.
- Logout retained project/search/status/severity/page state, hiding reports in the next account. Workspace filters, counts, selection and project-editing state are cleared on logout.
- Removing a screenshot left invalid annotation coordinates inside the report form, blocking submission. Removing/sending now clears the bitmap, pointer gesture, coordinates and capture label without losing report text.
- An exception while collecting private-region bounds happened outside the capture guard, leaving the overlay hidden and submission disabled. Preparation now shares the capture try/finally recovery path.
- ESLint scanned Playwright output while Playwright recreated it, causing an ENOENT failure. Generated browser artifacts are now explicitly ignored.

Six focused cases were reproduced against the previous application build. A seventh case covers refreshing the current search after a delayed mutation. Tests use fresh accounts, controlled request gates and response/paint completion, without arbitrary sleeps.
